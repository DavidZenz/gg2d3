<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions build -> downloadable artifact | Only validated pkgdown output should be uploaded as release evidence. |
| Downloaded artifact -> local inspector | The inspector must validate expected files and markers without trusting artifact names alone. |
| Repository docs layout -> publication layout | Helper code must avoid false negatives when the same site appears under `docs/` or as a site root. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-58-01 | Repudiation | workflow artifact | mitigate | Upload `docs/` only after `tools/validate-pkgdown-site.R --mode ci` passes. |
| T-58-02 | Tampering/Repudiation | publication inspector | mitigate | Validate exact article, NEWS, reference, widget, and sf markers using shared helper functions. |
| T-58-03 | Information Disclosure | workflow artifact contents | accept | Artifact contains public pkgdown site output already destined for GitHub Pages. |
| T-58-04 | Denial of Service | missing artifact files | mitigate | Use `if-no-files-found: error` so missing `docs/` does not silently produce empty evidence. |
</threat_model>
