<objective>
Harden live-browser sf interactivity so polygon, point, and line sf marks share the documented tooltip, hover, custom handler, Shiny-style handler, brush, sanitization, and zoom-suppression behavior.
</objective>

<threat_model>
## Threat Model

| Threat | Severity | Mitigation |
|--------|----------|------------|
| Renderer-private sf metadata leaks to user callbacks or Shiny inputs | high | Add browser assertions that tooltip text, custom handler payloads, shiny_id payloads, and brush callback rows exclude `_geom`, `_centroid`, `_sfFamily`, `_pointIndex`, and `_pointCoord`. |
| Multipoint or multiline child marks duplicate source rows during brushing | medium | Assert selected brush callback rows are deduplicated by source `row_id`. |
| Browser checks silently validate polygons only | medium | Build explicit point-only and line-only interaction fixtures and assert tags/classes include `circle.geom-sf-point` and `path.geom-sf-line`. |
| sf zoom suppression regresses while other interactions remain enabled | medium | Preserve an assertion that `d3_zoom()` warns, leaves brush/tooltip/hover/handlers enabled, and keeps `widget$x$interactivity$zoom` null for sf widgets. |
</threat_model>
