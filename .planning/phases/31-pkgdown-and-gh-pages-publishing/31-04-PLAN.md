    ```yaml
# Workflow derived from https://github.com/r-lib/actions/tree/v2/examples
# Need help debugging build failures? Start at https://github.com/r-lib/actions#where-to-find-help
on:
  push:
    branches: [main, master]
  pull_request:
  release:
    types: [published]
  workflow_dispatch:

name: pkgdown.yaml

permissions: read-all

jobs:
  pkgdown:
    runs-on: ubuntu-latest
    concurrency:
      group: pkgdown-${{ github.event_name != 'pull_request' || github.run_id }}
    env:
      GITHUB_PAT: ${{ secrets.GITHUB_TOKEN }}
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v6

      - uses: r-lib/actions/setup-pandoc@v2

      - uses: r-lib/actions/setup-r@v2

      - uses: r-lib/actions/setup-r-dependencies@v2
        with:
          extra-packages: any::pkgdown, local::.
          needs: website

      - name: Build site
        run: pkgdown::build_site_github_pages(new_process = FALSE, install = FALSE)
        shell: Rscript {0}

      - name: Deploy to GitHub pages 🚀
        if: github.event_name != 'pull_request'
        uses: JamesIves/github-pages-deploy-action@d92aa235d04922e8f08b40ce78cc5442fcfbfa2f # v4.8.0
        with:
          clean: false
          branch: gh-pages
          folder: docs
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → gh-pages branch on origin | Workflow has `contents: write`; minimum required to push the built site |
| Third-party action (`JamesIves/github-pages-deploy-action`) → repo content | Pinned by SHA, not tag; prevents tag-rewrite supply-chain attacks |
| GitHub Pages CDN → public users | Out of scope to harden; static HTML/JS only, no server-side execution |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-07 | T (Tampering) | Third-party `JamesIves/github-pages-deploy-action` malicious update via tag rewrite | mitigate | Action is pinned to SHA `d92aa235d04922e8f08b40ce78cc5442fcfbfa2f` (v4.8.0) verbatim from the r-lib template. Tag rewrites cannot affect us until we explicitly bump the SHA. Grep-verified: `grep 'JamesIves.*@d92aa235' .github/workflows/pkgdown.yaml` |
| T-31-08 | E (Elevation of privilege) | Overly broad GITHUB_TOKEN permissions | mitigate | Workflow scope is `permissions: read-all`; only the `pkgdown` job has `permissions: contents: write`. Pull requests build but cannot deploy (`if: github.event_name != 'pull_request'`). Minimum required for gh-pages push; no `id-token`, no `packages`, no `issues` write |
| T-31-09 | T (Tampering) | gh-pages branch overwrite is the intentional deploy mechanism (`clean: false`) — could be confused with destructive force-push | accept | Documented as intentional in this plan's threat model: `gh-pages` is a build-output branch, not source. `clean: false` means we keep prior files unless overwritten, which is fine for incremental site updates. Branch protection on gh-pages is unnecessary; users never PR against it |
| T-19-10 | I (Information disclosure) | Build logs from Actions could leak environment if a chunk accidentally `print()`s env vars | accept | Vignette chunks under our control; no `Sys.getenv` calls in current chunks per Phase 18 review. If added later, that's a Phase-N concern, not Phase 31 |
</threat_model>
