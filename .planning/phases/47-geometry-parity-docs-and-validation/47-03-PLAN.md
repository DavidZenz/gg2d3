<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Test suite -> validation evidence | Local command results become maintainer-facing support evidence. |
| Optional browser/spatial dependencies -> validation notes | Missing local `sf`, `chromote`, Chrome, or `geojsonsf` can be mistaken for unsupported package behavior. |
| Renderer/test internals -> validation artifact | Private renderer fields and implementation details can accidentally be framed as public API. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-47-01 | Information Disclosure | validation evidence artifact | mitigate | Tie evidence to sanitized public payload tests and avoid presenting renderer-private fields as public support contract. |
| T-47-02 | Tampering / Integrity | docs-validation handoff | mitigate | Keep evidence artifact command strings exact and RTK-prefixed; do not replace source-first docs regeneration from Plan 47-02 with validation-only notes. |
| T-47-03 | Repudiation | optional browser/spatial coverage | mitigate | Separate source/unit evidence from optional browser smoke and record pass versus explicit skip semantics for each optional command. |
</threat_model>
